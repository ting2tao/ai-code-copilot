## 1. 功能点

### F1 L0 SessionStart

`hooks/session-start` MUST only inject safety hard gates, command menu, framework path, optional context freshness warning, and optional active change summary.

### F2 Command-level Context Policy

`agents/copilot-prompt.md` MUST define `Context to load` for brainstorm/propose/apply/fix/fix-ci/review/finish/test/archive and MUST state that startup does not load all rules, packs, knowledge, or full spec.

### F3 Knowledge Retrieval

`knowledge/index.md` and generated project knowledge index MUST use a structured table with ID, Summary, Tags, Scope, Applies-To, Risk, Last-Verified, and File. `/propose` MUST score the index and load at most five knowledge files.

### F4 Log Compression

`changes/templates/log.md` MUST include Summary, Active decisions, Known risks, Review outcomes, Verification log, and Process notes. Compression MUST preserve commit hashes, verification commands/output, review FAIL reasons, and accepted risks.

### F5 Complex Isolation

`changes/templates/roadmap.md` and `tasks.md` MUST make each Complex sub-project an independent session and pass upstream context through `log.summary.md`, not full logs.

### F6 Context Freshness

`scripts/init_project.sh` MUST write `projectContextSyncedAt` and `projectContextStaleAfterDays`. `hooks/session-start` MUST soft-warn when project context is stale.

### F7 Review Feedback Hardening

The implementation MUST guard against silent failures introduced by the new context policy:
- malformed `summary.md` should trigger a SessionStart fallback warning
- small knowledge indexes should avoid unnecessary scoring overhead
- log compression thresholds should be project-configurable
- upstream `log.summary.md` should require owner review before downstream sub-projects start
- install scripts should warn when Python 3 is missing

### F8 Archive-Independent Runtime State

Runtime dependencies MUST be available before `/archive`:
- `summary.md` is created by `/propose`, updated by `/apply`, `/review`, and `/finish`, and marked `status: finished` by `/finish`
- SessionStart MUST ignore changes whose `summary.md` says `status: finished`
- Complex `log.summary.md` is generated by `/finish`, not only `/archive`
- `/finish` scans `Knowledge candidates` and offers optional knowledge capture before archive
- `/archive` remains cleanup and deeper knowledge capture, not the only source of runtime handoff files

## 2. 验收标准

- `bash scripts/check_framework.sh` passes.
- New project initialization creates `.copilot-state.json` with context freshness fields.
- New project initialization creates knowledge index with the structured schema.
- `bash -n hooks/session-start` and `bash -n scripts/init_project.sh` pass.
- Install scripts remain shell/PowerShell syntax valid.
- README documents the four context-management layers and fallback behavior.
- Finished changes are not injected as active changes by SessionStart.
